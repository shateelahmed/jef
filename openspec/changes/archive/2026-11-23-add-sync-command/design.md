## Context
jef commands are plain bash (3.2 on macOS). `lib/repos.sh` offers `parallel_run` (a worker per repository, output buffered in `$parallel_dir/<i>.out`, status in `<i>.rc`) and `parallel_apply_outcomes`; `lib/confirm.sh` offers `confirm_or_exit`.

## Decisions
- **Source of the merge/rebase** is the local default branch after it has been pulled with `git pull --ff-only origin <default>`. When the default branch cannot fast-forward the repository stops ("diverged"). When `origin/<default>` does not exist the pull is skipped.
- **Plan phase** reads only local refs (`git for-each-ref refs/heads`) in the main shell, into parallel indexed arrays (`plan_state`, `plan_branches`, `plan_count`), so the question can name branch and repository counts before any network access. A repository without a local default branch is "no <default>, skipped".
- **Worker** (`sync_repo_job`) runs in a background subshell, which inherits the plan arrays. It finds its index by comparing its directory with `repo_list` and writes one line per branch to `$parallel_dir/<index>.summary` as `status|branch|text` (status: ok, uptodate, local, fail, skipped), so `parallel_run` needs no change for that. It returns 0 (something changed), 1 (failed) or 2 (nothing to do, counted as skipped).
- **Stop on first failure** per repository: a failed pull, merge/rebase, push or checkout records the failure and marks the remaining branches "not attempted". Before stopping, `rebase_in_progress` (moved to `lib/repos.sh`) and `MERGE_HEAD` are checked and `rebase --abort` / `merge --abort` is run, so git is never left mid-operation. Dirty working trees are refused up front (nothing is changed). The original branch (or detached HEAD) is checked out again at the end where possible.
- **Push only when needed**: for a branch on `origin`, after pulling and merging/rebasing, push when the local tip differs from `refs/remotes/origin/<branch>`: `git push origin <b>` for merge, `git push --force-with-lease origin <b>` for rebase.
- **Pulling the branch**: `git pull --no-rebase --no-edit origin <b>` (merge) or `git pull --rebase origin <b>` (rebase), explicit so the user's `pull.rebase` setting does not matter.
- **-m** filter: copied from `jef merged`; because `parallel_run` would call `list_repos` again, `parallel_use_repo_list=true` makes it keep the narrowed `repo_list`. The list is built after `lib/clear-proxy.sh` is sourced (the banner shows "Jobs: all" when -j is not given), because `list_repos` runs git and must not see proxy variables when -c is used.
- **-j** has no default value; unset means one job per repository.
- **Output** is a tree like `jef merged` (`print_sync_plan` for the plan under "Will sync these branches" / "Would sync these branches", then the result under "Synced branches:"). The worker prints nothing: every git step runs through `sync_git`, which captures stdout and stderr; on failure `sync_set_detail` keeps up to 5 lines (CONFLICT lines, else the last lines) that are written to the summary file as `detail` lines and shown under the failed branch. After `parallel_apply_outcomes` (which only counts outcomes now, the buffers are empty) the main script reads the summary files and prints the totals and per-branch lines, coloured green (synced), yellow (up to date, local only), red (failed), dim (not attempted); `dim` is a new tput-based colour code.
- **Confirmation** is always asked (`confirm_or_exit` with "sync"/"synced") whenever at least one repository has the default branch; the dry run never asks.

## Risks
- Rebasing branches that contain merge commits flattens them (plain `git rebase`); acceptable and documented by the force-push warning in the question.
- Parallel runs of many repositories at once can be heavy: `-j` caps it.
